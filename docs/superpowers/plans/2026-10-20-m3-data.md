# Milestone 3 — Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `just simulate` generates a deterministic, labelled dataset of cloud-audit, Kubernetes and
identity events in the challenge's proportions, replays it onto Redis Stream `events.raw`, and a
`worker` process normalizes every record into the OCSF-inspired `Event`, stores it idempotently in
Postgres (`core.events`), dead-letters invalid records to `events.dlq`, and survives crashes via
consumer-group ACK + `XAUTOCLAIM`. Analysts can page through stored events at `GET /api/v1/events`.

**Architecture:** Two new uv workspace packages: `libs/py/detection-core` (`ephoros_detection`:
`Event` model, UUIDv7, source normalizers — framework-free) and `libs/py/simulator`
(`ephoros_sim`: seeded scenario generator, label writer, replay CLI `ephoros-sim`). The API package
gains its hexagonal layers: `domain/ports.py`, `services/ingest.py`, `adapters/db/*` (SQLAlchemy 2
async + Alembic, schema `core`), `adapters/redis_streams.py`, and `entrypoints/worker.py`.
import-linter enforces the layering. Compose gains a `worker` service from the API image.

**Tech Stack:** SQLAlchemy 2.1.5 (asyncio) · Alembic 1.20.0 · redis-py 8.1.0 (Streams) ·
testcontainers 4.15.0 (Postgres + Redis) · import-linter 2.15 · pydantic 2 · Python 3.13.

**Spec:** `docs/superpowers/specs/2026-10-10-ephoros-design.md` (§4.2–4.4, §5, §6.1, §7 Normalize, §9.2 Events, §12, §16, §17.3).

## Global Constraints

- Everything in the M1/M2 plans' Global Constraints still holds. Run commands under `eval "$(mise env -s bash)"`.
- Pins: `sqlalchemy[asyncio]==2.1.5`, `alembic==1.20.0`, `testcontainers[postgres,redis]==4.15.0`,
  `import-linter==2.15`. No UUID library: UUIDv7 is a 10-line helper (Python 3.13 has no `uuid.uuid7`,
  and the simulator needs seeded, reproducible IDs).
- `Event` fields exactly as spec §5.1. Enums: `source ∈ {cloud_audit, k8s, identity}`,
  `category ∈ {api_activity, resource_lifecycle, session, rbac}`, `outcome ∈ {success, failure}`,
  `principal_type ∈ {user, service_account, role, federated}`. `action` is validated against a fixed
  `ACTIONS` set (spec: "enum-validated").
- Stream envelope (the only thing on `events.raw`):
  `{"event_id": <uuid7>, "source": <source>, "raw": <JSON string of the source record>}`. The event id
  is assigned by the producer (simulator now, k8s-watcher in M8) so labels can reference it.
  **Labels never travel on the stream** — they go straight to `core.event_labels` (spec §5.2: read only
  by the evaluation harness).
- Streams/groups: `events.raw` (group `workers`), `events.dlq` (`{event_id, source, reason, raw}`).
  Pending entries idle > 60 s are reclaimed with `XAUTOCLAIM`. Inserts are
  `ON CONFLICT (event_id) DO NOTHING` (idempotent, spec §16).
- Simulator counts per run (spec §6.1): cloud 500–1000, k8s 500–1000, identity 200–500. Scenario mix
  by **scenario instances**: crypto-mining 5–8 %, public exposure 3–5 %, unexpected identity 5–8 %,
  legitimate bursts 40–50 %, routine lifecycle 30–40 %. Same `--seed` + `--start` ⇒ byte-identical output.
- Timestamps are absolute UTC. `--start` defaults to now (second precision) so a live replay at
  `--speed 1` produces realistic latency; evaluation runs pass an explicit `--start`.
- DB: tables in schema `core`; Alembic version table `core.alembic_version`; `just migrate` runs
  Alembic and the auth Drizzle migrations. `DATABASE_URL` stays `postgresql://…`; the SQLAlchemy
  adapter switches the driver to `postgresql+asyncpg`.
- Out of scope (later milestones): enrichment/assets/identities/sessions tables and classification (M4),
  detections (M4+), SSE (M5), DLQ admin view (M7), k8s-watcher (M8).

### Per-task workflow (unchanged)

TDD → ponytail smallest code → verification-before-completion → ponytail-review → fix → commit
(check the commit landed: `&& echo committed`). Milestone end: fresh whole-branch review →
ponytail-debt → finishing-a-development-branch.

## Review Focus

1. **Worker crashes after storing but before ACK** — redelivery must not duplicate rows; a message
   stuck in another consumer's pending list must be reclaimed. Tests in Task 5:
   `test_redelivered_message_is_stored_once`, `test_stuck_pending_message_is_reclaimed`.
2. **Database down mid-batch** — messages must stay pending (not ACKed, not DLQ'd) and be processed
   when the DB returns. Test in Task 5: `test_store_failure_leaves_messages_pending`.
3. **Garbage on the stream** (non-JSON, unknown source, missing fields, unknown action) — DLQ with a
   reason, ACKed, worker keeps going. Test in Task 5: `test_invalid_records_go_to_dlq`.
4. **Ground-truth leakage** — nothing in `events.raw`, `core.events` or the normalized `Event` may
   contain scenario names or malicious flags. Test in Task 6: `test_stream_carries_no_labels`.
5. **Simulator drift** — a changed generator silently changes the evaluation dataset. Test in Task 3:
   `test_same_seed_is_byte_identical` plus a golden digest for seed 7.

### Task 3: Simulator — seeded, labelled scenario generator

**Files:**

- Create: `libs/py/simulator/pyproject.toml` (script `ephoros-sim = "ephoros_sim.cli:main"`),
  `libs/py/simulator/project.json`, `libs/py/simulator/src/ephoros_sim/{__init__,model,world,generate}.py`,
  `libs/py/simulator/src/ephoros_sim/scenarios/{__init__,routine,legit_burst,crypto_mining,exposure,identity_anomaly}.py`,
  `libs/py/simulator/tests/test_generate.py`

**Interfaces:**

- Consumes: `uuid7`, `normalize` (tests only — the generator never imports detection logic).
- Produces:
  - `model.py`: `Label(scenario: str, is_malicious: bool, severity: Literal['none','low','medium','high','critical'], scenario_instance_id: str)`,
    `SimRecord(event_id: UUID, source: Source, raw: dict, observed_at: datetime, label: Label)`.
  - `world.py`: `World` — seeded fixed cast: 3 accounts/regions, 6 namespaces (incl. `ci`, `payments`),
    ~20 human users, ~10 service accounts (incl. a shared `deployer` SA), 2 federated IdPs, home IP ranges
    and countries per user, working hours.
  - `generate(seed: int, start: datetime, hours: float = 6.0) -> list[SimRecord]` — sorted by
    `observed_at`; each scenario module exposes `instance(world, rng, t0) -> list[SimRecord]`
    producing one scenario instance (all its events share `scenario_instance_id`).
  - Scenarios (each with the ambiguity case the spec names, spec §6.1):
    - `routine_lifecycle` (benign): deployments/replicasets, long-lived pods, scheduled instance changes,
      normal logins.
    - `legit_burst` (benign): CI Job bursts in `ci` (owner Job, `ci.ephoros.io/pipeline` label, short
      TTL) and autoscaler scale-outs (spot instances tagged `autoscaler`) — _twins of the attacks_.
    - `crypto_mining` (malicious, high/critical): stolen SA token from a new IP creates a privileged,
      controller-less pod with a miner-like image/command (busybox loop name, no real miner), maybe a
      GPU spot `RunInstances` burst; resources deleted within minutes (_deleted before triage_).
    - `public_exposure` (malicious, medium/high): NodePort/LoadBalancer service on a debug pod, or
      security group opened to `0.0.0.0/0`; sometimes a benign twin in a sandbox namespace labelled
      `exposure=approved` (benign, low).
    - `identity_anomaly` (malicious, medium/high): off-hours login from a new country, then
      `AssumeRole` + `CreateAccessKey`; includes _automation vs stolen token_ (same SA, new IP) and a
      _federated_ identity variant; shared `deployer` SA used by CI too.
  - Instance counts are drawn so per-run event totals and the scenario mix land in the Global
    Constraints ranges; `generate` asserts them (raises if a seed falls outside — never silently).
  - Nx project `simulator` (`type:app,scope:py`) with `test`, `lint`, `typecheck`.
